# Joy-style SNS 포스팅 스타일 가이드

기존에 작성한 인스타그램 포스팅 글들을 모아 스타일을 분석한 문서. 앞으로 이 프로젝트에서 SNS용 본문/해시태그를 쓸 때 이 톤과 구조를 기본으로 따라간다.

## 스타일 요약

**정체성 / 시그니처**
- 개인 브랜드 태그 `Joy-style` / `#joystyle` 이 거의 모든 포스팅에 등장 (본문 태그라인 또는 해시태그).
- 여행 시리즈는 `Joy-style solo travel in Chiang Mai / 30s challenge` 라는 고정 태그라인을 씀.

**언어 구성 (한/영 패턴)**
- 세 가지 방식이 섞여 있음, 내용 성격에 따라 선택:
  1. **영어만** — 가볍고 짧은 순간 포스팅 (예: "Cooool girl", "Drawing trip", 스도쿠 에피소드의 요약 문장)
  2. **한국어 → 영어 번역/요약** 순서 — 긴 서사형 포스팅 (혼자 여행 마무리 글, Think Lab 소개 글). 직역이 아니라 같은 내용을 한 번 더 풀어쓰는 방식. `.` 한 줄이나 `[EN]` 으로 구간을 나누기도 함.
  3. **한국어만** — 국내 네트워크/커리어 관련 포스팅 (송상수님 스토리, 백패킹 후기 일부)
- 영문 버전은 한글보다 더 담백하고 정제된 문장으로 요약하는 편 (문장 수를 줄임).

**톤**
- 1인칭 일기체, 담백하면서 솔직함. 감정을 과장하지 않고 담담하게 서술.
- 여행/일상 포스팅: 유머러스하고 자기 자신을 캐릭터처럼 부르는 표현 사용 ("나야 나", "청개구리 모먼트 🐸 개굴", "다이소 참새").
- 감성적인 마무리 포스팅(여행 종료, 우정 등): 감정을 진솔하게 표현하되 담백함 유지. 과한 수식어 없음.
- 커리어/프로젝트 포스팅: 비전과 철학을 진지하게, 그러나 여전히 개인적인 목소리로 서술 ("저는 요즘 새롭게 미래를 꿈꾸고 있습니다").

**구조 패턴**
- 짧은 포스팅: 제목 같은 한 줄 + 활동 스탯(거리/시간 등, 있는 경우) + 태그라인 + 해시태그. 문단 구분 없이 3~5줄.
- 에피소드형 포스팅: 상황 묘사 → 디테일/에피소드 → 소감 한 줄 → (영문 요약) → 해시태그.
- 서사형 마무리 포스팅: 한국어 여러 문단 → 빈 줄 → 영문 여러 문단(같은 내용 재구성) → 해시태그. 문단은 2~4문장 단위로 짧게 끊음.
- 커리어 포스팅: 비전 문장 → 근황/프로젝트 소개 → `📚 Background` 같은 이모지+제목 리스트 섹션 → `.` 구분선 → `[EN]` 짧은 영문 요약.
- 구분 기호: `.` 한 줄씩 여러 번 (섹션 전환), `✏` (포인트 표시), 굵은 이모지 헤더 (`📚`, `🔥`).

**해시태그 규칙**
- 코어 세트(여행/일상): `#joystyle #travel` 줄바꿈 `#chiangmai #thailand 🇹🇭` 줄바꿈 + 주제별 태그 1개 (`#hiking`, `#sketchbook`, `#movie`, `#friends`, `#sudoku`).
- 코어 세트(커리어): `#joystyle #career` 줄바꿈 `#edu #ai #programming`.
- 항상 소문자, 띄어쓰기 없이, 국기 이모지(🇹🇭)는 hashtag 옆이 아니라 `#thailand` 바로 뒤에 붙임.
- 해시태그는 항상 본문 맨 마지막, 빈 줄로 구분.

**이모지 사용**
- 문장 끝이나 주제를 함축하는 이모지 1~2개 사용 (⛰️🎨🥺😎🛫💙🐸🌿🔥📚💪). 과도하게 남발하지 않음.

## 앞으로 적용 방법

- 치앙마이 AI 교육 프로젝트 포스팅도 이 톤(담백한 1인칭, 감정 과장 없음)과 해시태그 구조(`#joystyle` 포함 여부는 상황에 따라 판단, 여행 코어 태그는 유지)를 기본으로 초안 작성.
- 내용 성격에 따라 위 3가지 언어 구성 중 적절한 것을 선택 (짧은 순간 vs 서사형 vs 국내용).
- `/sns-posting`(`/posting`) 커맨드로 포스팅을 만들고, 최종본이 확정되면 자동으로 `history/` 아래에 파일로 적재되고 `history/INDEX.md`에 한 줄 추가된다.

## 원문 레퍼런스

전체 원문(기존 포스팅 + 확정된 신규 포스팅, 시간순)은 `history/INDEX.md`에서 목차로 확인하고, 각 항목의 파일 링크를 따라가면 된다. 포스트 1개 = 파일 1개 원칙 (연도별 폴더, 레거시는 `history/legacy/`). 이 문서에는 스타일 요약만 유지한다.
